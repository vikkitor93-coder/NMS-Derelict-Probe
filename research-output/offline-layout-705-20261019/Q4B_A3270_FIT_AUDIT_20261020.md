## 3. Discrepancies found and fixed (observed)

| # | Native | Old port | Effect |
|---|---|---|---|
| D1 | Out-of-grid: `test bpl,bpl` at 0x39FF. BPL is **candidate byte 3** (`qword>>0x18`, 0x3339). | Tested `expected_neighbor_tag != 0`. | Every out-of-grid cell was rejected for every room except room 0. |
| D2 | Table `0x3A3AD4[0]` = `0x3A34F1`: in-grid **opcode 0 accepts any cell type**. Only opcode 2 (`0x3458`) needs type ≤ 1. | Opcode 0 required type ≤ 1. | Opcode 0 is used by almost every map cell. |
| D3 | Not-same-tag path: `mov sil,1` and save to `[rsp+24h]` (0x34F7). When byte0&4 is set and the directional test misses, the flag stays 1 and goes to the range check (0x37A3). | The flag stayed 0, so the cell was always rejected. | |
| D4 | The 0x08 scan stops at the **first** direction whose neighbor matches both tag and type (0x3785 → 0x384C). A failed A4120 call or a clear bit 0x10 ends the scan at 0x379F. | Kept scanning the remaining directions. | |
| D5 | The 0x08 scan's fallback restores `[rsp+24h]` (1, or 0x40 from the first scan) at 0x379F. | Reset to 0, then 1, so a 0x40 result was lost. | |
| D6 | Byte-5 connection path at 0x37DD–0x3A50. The target is (origin-3, origin-2, origin-3). A two-way neighbor test via `(byte0^0x20)>>5` gives a hit; reject if `sel == (2 if hit else 1)`. | `NotImplementedError` | Moot here: all 12,520 non-empty native cells have byte5 = 0. |

The out-of-grid jump index (`0x3A3B9C`) matched the old port:
- Opcodes 0 and 1 go to the byte5/byte0&2 test.
- Opcodes 8–13 go to `0x3A33` (`cmp sil,0Eh`), which can never be true for them, so they are rejected.
- All other opcodes are rejected.

The fix is in `nms_dungeon_fit_705_q4b.py`, with the same signature plus `fit_reason_705`.

## 4. Live rows compared with the Q4 provider (observed)

- **Same table.** Both have 1,876 rows and 319 keys, and the descriptor-key sequence is identical row for row.
- **Map bytes are nearly identical.** 1,871 of the 1,876 0x25E prefixes are byte-identical.
  - The 5 that differ are orientation-dimension swaps: DOOR_SLIME, DOOR_SLIME_B, DOOR_, DOOR_B and R_OC_DIVIDER have native (1,1,2) where the port has (2,1,1), and (4,1,2) vs (2,1,4).
  - Distinct prefixes: 334 native vs 333 port.
- **R_W_CAPT (row 1390) is identical.** See `Q4B_LIVE_ROW_COMPARE_20261020.json`.
- **Conclusion: the map bytes are not the cause.**

## 6. Why it still fails (observed and inferred)

- **Observed: the grid byte 4 can never satisfy R_W_CAPT.** R_W_CAPT's centre cell needs `grid byte4 & 0x23 == 0x01`. At the first A2780 call, every grid cell has byte4 of 0x00 or 0xFF.
- **Observed: walls and floors provide that bit.** Native wall/floor rows set byte4 bit 0 through A5480 (R_W*, R_F*, R_IC*: centre b4 = 0x01).
- **Inferred: the quest failure is a downstream effect.** Too few layer-2 walls are placed before the layer-5 quest piece.
- **Observed: the 0xFF cells block most pieces.** Each room's owned cells include 3–4 cells with byte0 = 0xC0 (type 6) and byte4 = 0xFF. They block every piece cell with mask 0x02 (most cells of R_F3/R_W3).
- **Inferred: the remaining gap is the grid producer, not A3270 or the map bytes.** It is the topology / A1DA0-stage state: byte0 type and flags, and byte4 = 0xFF. This is unverified.

## 7. Unknowns, and what would settle them

- **The native grid before A2780** (5-byte cells; W/H/D at DungeonParams +0x60). One capture at A2780 entry decides whether the port's byte0/byte4 grid (above all the type-6 / 0xFF cells) matches native.
- **Next static step:** audit the grid writers that set byte4 = 0xFF and type 6.
- **Orientation-swapped dims** for the 5 door and divider rows (§4). These are minor.
